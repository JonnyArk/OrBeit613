## 2024-03-05 - Secured AI Endpoints with verifyAuth Helper
**Vulnerability:** The `generateAsset`, `distillContext`, and `creditUsage` functions were exposed as public HTTP endpoints (`onRequest`) without authentication, allowing unauthorized users to invoke them, potentially consuming expensive AI credits (`getWhiskService`, `getFlowService`) with no tracking.
**Learning:** The endpoints used `onRequest` instead of `onCall`, presumably for client API compatibility or architectural reasons. Because `onRequest` does not automatically attach `request.auth`, developers must manually verify the authorization header using `firebase-admin/auth`. Without this explicit verification, the endpoints remain completely open. Furthermore, injecting the validated `userId` strictly from the decoded JWT into the request payload prevents spoofing.
**Prevention:** Whenever exposing sensitive functionality via Firebase `onRequest` functions, immediately implement a JWT verification middleware or helper (`getAuth().verifyIdToken()`). Relying solely on client-provided IDs inside the HTTP body is insecure. Additionally, always type `response` as `Response` from `express` to satisfy strict linting.
