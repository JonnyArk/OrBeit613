## 2025-03-04 - Fix missing authentication on AI endpoints
**Vulnerability:** Backend AI services (`generateAsset`, `distillContext`, `creditUsage`) were implemented using `onRequest`, exposing them as public HTTP endpoints without authentication or structured input validation.
**Learning:** `onRequest` relies on manual request processing and does not natively populate Firebase Authentication context (`request.auth`), leading to potential unauthorized access and insecure trust of client-provided User IDs. While `onCall` automatically validates the authentication token, converting an existing `onRequest` to `onCall` is a breaking change to the API contract because `onCall` expects a specific JSON envelope.
**Prevention:** When adding authentication to existing `onRequest` endpoints to avoid breaking client contracts, use manual verification of the `Authorization` header via `admin.auth().verifyIdToken()`. Extract the user's secure ID (`decodedToken.uid`) instead of relying on client-provided IDs.
