## 2025-03-09 - Securing onRequest Endpoints from IDOR and Denial of Wallet
**Vulnerability:** The AI worker endpoints `generateAsset` and `distillContext` were publicly accessible `onRequest` functions that blindly trusted the `userId` in the request payload. This permitted unauthenticated users to trigger heavy computations and consume valuable credits (Denial of Wallet). Furthermore, authenticated users could spoof another user's ID via payload manipulation (IDOR) to create fake content.
**Learning:** By design, Firebase HTTP `onRequest` endpoints do not populate `request.auth` automatically (unlike `onCall`). Developers sometimes mistakenly assume they are protected or attempt to access `request.auth`.
**Prevention:** For any sensitive or resource-intensive `onRequest` function, implement manual Bearer token parsing and validation via `admin.auth().verifyIdToken()`. Additionally, always extract the authenticated `uid` from the token verification and unconditionally overwrite any payload-provided `userId` (e.g., `body.userId = uid`) before processing to prevent IDOR vulnerabilities.
