## 2026-05-15 - Missing Authentication on Billing-Sensitive Cloud Functions
**Vulnerability:** The `generateAsset` and `distillContext` AI Cloud Functions were implemented using Firebase v2 `onRequest` handlers but lacked authentication checks. Since these endpoints directly consume paid AI resources, this allowed unauthenticated external access to trigger API calls and incur costs (Denial of Wallet). Error messages were also returned directly to the client, leaking internal details.
**Learning:** Unlike Firebase `onCall` functions, v2 `onRequest` functions are public by default and do not automatically enforce Firebase Authentication. Any HTTP endpoint that consumes credits or performs sensitive operations must explicitly verify auth tokens. Furthermore, internal error details should never be passed back to the client.
**Prevention:** Always use a custom `requireAuth` middleware/helper that validates the `Authorization: Bearer <token>` header via `getAuth().verifyIdToken()` for any `onRequest` function. Catch and log errors internally while returning generic HTTP error responses (e.g., 500 Internal Server Error) to the client.
