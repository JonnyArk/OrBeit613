## 2024-03-22 - Missing Authentication on Sensitive v2 Endpoints
**Vulnerability:** Firebase v2 `onRequest` endpoints (`generateAsset` and `distillContext`) process user-specific actions and record credit usage by `userId` (passed from the client body) without verifying authentication status or the `userId`'s authenticity. This creates a critical IDOR (Insecure Direct Object Reference) and authorization bypass. A malicious user could call these endpoints with arbitrary `userId`s, consuming other users' credits or generating assets maliciously.
**Learning:** In Firebase Cloud Functions v2, `onRequest` HTTP endpoints do not have built-in authentication context (unlike `onCall` functions). To secure them, we must manually extract the Bearer token from `request.headers.authorization` and verify it using `getAuth().verifyIdToken()` from `firebase-admin/auth`. Also, we must *never trust client-provided user IDs* in request payloads. We must always strictly overwrite the payload's user ID with the verified identity extracted from the server-side authentication token.
**Prevention:** Always use `onCall` if possible for authenticated functions, or strictly implement manual Bearer token verification + overriding user IDs for `onRequest` endpoints.
