## 2024-03-19 - Fix Authorization Bypass & IDOR in AI Endpoints
**Vulnerability:** The AI backend endpoints (`generateAsset` and `distillContext`) deployed as standard public HTTP endpoints (`onRequest`) completely lacked authentication, meaning anyone could call the API and consume credits. Additionally, the endpoints trusted the `userId` provided by the client in the request body, leading to an Insecure Direct Object Reference (IDOR) allowing arbitrary resource generation or tracking against spoofed user IDs.
**Learning:** These AI endpoints were likely deployed this way rather than as `onCall` (Callable Functions) to maintain a pure RESTful interface. However, unlike `onCall` functions which automatically handle and attach `request.auth`, `onRequest` endpoints require manual verification of the authorization headers using `getAuth().verifyIdToken()`. Relying on client-provided metadata like `userId` in `onRequest` bodies is insecure.
**Prevention:** For public `onRequest` HTTP endpoints, always implement explicit header-based authorization token checks (`verifyIdToken`). Securely extract the `uid` from the verified token and overwrite/inject this verified identity into the request payload or service handlers to prevent spoofing and IDOR vulnerabilities.
