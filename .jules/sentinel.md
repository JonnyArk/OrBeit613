## 2023-10-27 - Unauthenticated Callable Functions Vulnerability
**Vulnerability:** Core AI endpoints (`generateAsset`, `distillContext`) and `creditUsage` were implemented as `onRequest` HTTP functions without authentication, allowing anyone to drain AI credits and accessing other user's info. They were also implicitly trusting the client-provided `userId` which allowed spoofing usage as other users. The public `healthCheck` also leaked credit usage totals.
**Learning:** In Firebase, sensitive business operations (especially those tracking usage or accessing user data) should be implemented using `onCall` (Callable Functions), which automatically handles CORS and injects `request.auth` info. It is critical to enforce `if (!request.auth)` checks in all callable functions, and to unwrap the payload via `request.data`. Furthermore, we should never trust client-provided identities and always explicitly inject `userId = request.auth.uid` before passing the data to the backend services.
**Prevention:** Always use `onCall` for API endpoints that require authentication. Explicitly enforce `if (!request.auth)` constraints and rely only on `request.auth.uid` for identifying the current user. Remove sensitive business metrics from public health checks.
