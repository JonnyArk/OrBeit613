## 2025-05-04 - Unauthenticated Access on Sensitive v2 onRequest Cloud Functions
**Vulnerability:** Firebase v2 `onRequest` cloud functions (like `creditUsage`, `generateAsset`, and `distillContext`) lacked authentication, allowing unauthenticated users to access AI credit usage data and maliciously generate AI assets or distill contexts via POST requests, bypassing Firebase Cloud Functions' default lack of authentication on webhooks.
**Learning:** By default, Firebase Cloud Functions v2 `onRequest` are public. Without explicitly wrapping them with an authentication verification logic (`getAuth().verifyIdToken`), they are highly vulnerable to IDOR, resource abuse, and cost exhaustion. The `userId` derived directly from `request.body` cannot be trusted.
**Prevention:** Always implement explicit authentication checking for `onRequest` cloud functions that require user context. Verify Firebase ID tokens, handle unauthenticated requests gracefully with generic HTTP error responses to prevent information leakage, and derive sensitive payload metadata (e.g., `userId`) strictly from the authenticated token instead of trusting client payloads.
