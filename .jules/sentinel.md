## 2024-05-18 - [CRITICAL] Fix unauthenticated access and IDOR in AI endpoints
**Vulnerability:** The AI Cloud Functions (`generateAsset`, `distillContext`, `creditUsage`) were exposed as public `onRequest` HTTP endpoints without any authentication verification. Additionally, the `userId` passed to backend AI logic for usage tracking was read blindly from the client payload (`request.body.userId`), allowing IDOR (Insecure Direct Object Reference) and spoofing attacks.
**Learning:** Cloud Functions built with `onRequest` (unlike `onCall`) do not automatically populate `request.auth`. If the developer assumed authentication was handled, it leaves sensitive APIs completely open. Furthermore, backend business logic must rely on a securely derived user identity, not client-provided IDs.
**Prevention:** Always verify standard HTTP endpoints with `getAuth().verifyIdToken()` before processing the request. Explicitly inject the secure `uid` from the token into business logic data payloads instead of trusting the client-supplied user ID.
