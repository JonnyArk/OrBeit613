## 2023-11-20 - Unauthenticated and Insecure Firebase Endpoints
**Vulnerability:** Several sensitive functions (`generateAsset`, `distillContext`, `creditUsage`) were exposed as public `onRequest` HTTP endpoints, lacking authentication and accepting arbitrary input directly from the request body without validation or user isolation. The `userId` was either missing or potentially user-supplied instead of securely injected from context.
**Learning:** Firebase functions intended for authenticated client use should use `onCall` rather than `onRequest`. `onCall` automatically validates the authentication token and provides a trusted `request.auth` context. By using `onRequest`, the application was susceptible to unauthorized access and potential abuse of its AI APIs (consuming credits with unverified payloads).
**Prevention:** For any endpoint that is supposed to be accessed strictly by authenticated users, use `onCall` and verify `request.auth` instead of `onRequest`. Always extract critical information like `userId` from the verified `request.auth.uid` instead of trusting client payloads.
