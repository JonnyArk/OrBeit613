## YYYY-MM-DD - Missing Authentication on Firebase HTTP Functions
**Vulnerability:** HTTP functions (like `generateAsset` and `distillContext`) process user requests and use AI credits (associated with a secret key) but lack authentication/authorization checks. They are wide open to the internet.
**Learning:** Firebase `onRequest` endpoints are unauthenticated by default. If we don't manually verify the caller's identity (e.g. Firebase Auth tokens), anyone can invoke the function, potentially causing a Denial of Wallet attack or accessing unauthorized functionality. The `healthCheck` is public by design, but `generateAsset` and `distillContext` should be authenticated.
**Prevention:** Always verify Firebase Auth tokens or use `onCall` functions which automatically include auth context instead of `onRequest` for endpoints that require authentication. When manually verifying Bearer tokens in Firebase `onRequest` endpoints using `getAuth().verifyIdToken()`, always wrap the verification in a `try...catch` block that returns a `401 Unauthorized` response.
