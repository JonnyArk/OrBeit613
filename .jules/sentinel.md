## 2024-03-20 - Missing Authentication and IDOR in AI Service HTTP Endpoints
**Vulnerability:** The AI Service HTTP endpoints (`creditUsage`, `generateAsset`, `distillContext`) deployed via `onRequest` lacked authentication checks and relied entirely on the client-provided `userId` within the request body. This allowed any unauthenticated user to trigger costly AI operations and exposed an Insecure Direct Object Reference (IDOR) vulnerability where authenticated users could spoof the `userId` payload to attribute AI usage or access data under other users' accounts.
**Learning:** Cloud Functions built with `onRequest` (HTTP functions) do not automatically populate `request.auth` like `onCall` functions do. Therefore, authorization headers must be explicitly extracted and validated using `getAuth().verifyIdToken()`.
**Prevention:** For any sensitive operation exposed via `onRequest`, always manually extract the Bearer token, verify it, and strictly enforce identity by explicitly overwriting client-provided user IDs (e.g., `body.userId = uid`) with the authenticated UID derived from the token. Do not trust client-supplied identity payloads.
