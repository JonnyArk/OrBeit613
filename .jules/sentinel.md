## 2024-05-24 - Missing Auth on Sensitive Firebase v2 Endpoints
**Vulnerability:** Firebase v2 `onRequest` functions are public by default. The `generateAsset` and `distillContext` functions process sensitive user data and consume paid AI credits without explicitly enforcing authentication.
**Learning:** Unlike Callable functions (`onCall`), which include built-in Firebase authentication context (`request.auth`), `onRequest` endpoints do not automatically verify users. Even though the codebase standard requires tracking usage per user (`userId`), there is no validation to prevent unauthorized users (or bots) from submitting requests. This can lead to unauthorized data exposure and rapid depletion of the 25k monthly AI credits.
**Prevention:** Always implement an explicit ID token verification check (e.g., using `getAuth().verifyIdToken()`) at the beginning of all `onRequest` functions that are not intended to be fully public. Use structural typing in TypeScript for Express-like responses to avoid missing type issues. Fail securely with generic error messages like "Unauthorized: Invalid token".
