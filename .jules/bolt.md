## 2024-09-25 - ListView.builder Virtualization Pattern in Flutter

**Learning:** In Flutter, using `ListView` with a predefined list of children (e.g., `children: [...]`) forces all items to be built eagerly, negating the performance benefits of virtualized rendering. When dealing with heterogeneous lists (e.g., headers interspersed with items), building an array of pre-instantiated widgets is an anti-pattern. Eagerly building large lists can cause O(N) memory allocations and dropped frames. Also, using initial staggered animations on lazily mounted items in `ListView.builder` can cause visual popping; stripping them entirely introduces regressions, cap the stagger delay conditionally based on the list position (e.g., `index < 10`).

**Action:** Map the data model into a flattened list of view models or enums/records that represent each item, and use `ListView.builder` to dynamically evaluate and build them inside the `itemBuilder` callback. This maintains O(1) rendering cost regardless of list size. Use a switch statement with pattern matching (destructuring) on the item record to handle the different item types gracefully. Use `ListView.builder` over `ListView(children: ...)` for any list that may grow beyond a handful of items.
