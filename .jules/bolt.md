## 2024-10-16 - Flutter ListView lazy evaluation and Riverpod assertions
**Learning:** In Flutter, `ListView.builder` evaluates its `itemBuilder` callback lazily during the layout phase, which is after the parent widget's `build` method has completed. Because of this, calling Riverpod's `ref.watch()` directly inside the `itemBuilder` (or inside helper methods called by `itemBuilder`) triggers a runtime exception: `Cannot use "ref.watch" outside of the "build" method of a widget`. Additionally, replacing simple local widget state with complex Riverpod providers for a single widget violates Bolt's constraints against making broad architectural changes for performance.
**Action:** Always extract the watched provider state into a separate `ConsumerWidget` or watch it at the top level of the parent's `build` method and pass the value down. Furthermore, prefer simple inline array flattening inside the `build` method for small lists over introducing new global providers when optimizing list rendering to adhere to strict architectural boundaries.
