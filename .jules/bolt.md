## 2024-05-18 - Optimize ListView implementation
**Learning:** Passing pre-instantiated widgets into `ListView` or `ListView.builder` negates its lazy-loading performance benefits. Attempting to optimize this by eagerly building an array of closures (e.g., `List<Widget Function()>`) is an anti-pattern that still causes O(N) upfront allocations and sacrifices readability. To correctly virtualize heterogeneous lists, map the data model into a flat list of items and dynamically evaluate them inside the `itemBuilder` callback. While initial staggered animations on lazily mounted items cause visual popping, stripping them entirely introduces regressions; cap the stagger delay conditionally based on the list position (e.g., `index < 10`).
**Action:** Always use `ListView.builder` and evaluate items directly within the `itemBuilder` function. Cap animation delays for items outside the initial viewport.
